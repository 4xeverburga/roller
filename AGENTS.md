# AGENTS — Running Roller

Roller is a multi-user, multi-weblog blog server. Visitors read weblogs,
entries, comments and feeds; authors sign in to `/roller-ui/` to write
entries, moderate comments, manage bookmarks, media files and themes; an
administrator manages users, weblogs and the site's runtime properties.

Stack: Struts 2.5 actions + JSP (`app/src/main/webapp/WEB-INF/jsps/`) for
the authoring and admin UI, Velocity templates for the rendered weblogs,
JPA (EclipseLink) over MySQL, Guice for wiring, built as a Maven WAR. The
sources are Java 7 and the toolchain installed here is JDK 8.

| Thing | Where | Notes |
|---|---|---|
| **JDK 8** | `JAVA_HOME`; `java`, `javac`, `jar` on the path | |
| **Maven** | `mvn` on the path | |
| **Tomcat 9** | `$CATALINA_HOME` | `javax.servlet`; Tomcat 10+ moves to `jakarta.servlet` and will NOT work. |
| **Server jars** | `$CATALINA_HOME/lib` | MySQL Connector/J 5.1.49, JavaMail 1.4.7, JAF 1.1.1 — the WAR ships none of them. |
| **MySQL 5.7** | `db:3306` (see below) | |

---

## 1. The database

MySQL 5.7 at `db:3306`, user `root`, password `roller`, database
`rollerdb` (UTF-8). Use that host, not `localhost`: the server is not on
this machine, only the `mysql` client is.

The schema is generated by the build, per database, from
`app/src/main/resources/sql/createdb.vm`. Load it once, after the first
build (§2), into an empty `rollerdb`:

```bash
mysql -h db -uroot -proller --default-character-set=utf8 rollerdb \
  < app/target/dbscripts/mysql/createdb.sql
```

To start over, drop and recreate the database, then load it again:

```bash
mysql -h db -uroot -proller -e 'DROP DATABASE rollerdb;
  CREATE DATABASE rollerdb DEFAULT CHARACTER SET utf8 COLLATE utf8_general_ci'
```

A fresh schema has no users and no weblogs. The front page then offers to
register one: **the first user to register becomes the administrator.**

## 2. Build

```bash
mvn -B -q -DskipTests package     # -> app/target/roller.war
```

`-o` works offline once the dependencies are in `~/.m2`. The tests need a
Derby database of their own; skip them for a plain build.

## 3. The config the app reads

Roller reads `roller-custom.properties` from the classpath, on top of the
defaults in `app/src/main/resources/org/apache/roller/weblogger/config/roller.properties`.
Put it in `$CATALINA_HOME/lib/`:

```properties
installation.type=manual
database.configurationType=jdbc
database.jdbc.driverClass=com.mysql.jdbc.Driver
database.jdbc.connectionURL=jdbc:mysql://db:3306/rollerdb?autoReconnect=true&useUnicode=true&characterEncoding=utf-8&mysqlEncoding=utf8&useSSL=false
database.jdbc.username=root
database.jdbc.password=roller
mail.configurationType=properties
mail.hostname=localhost
mediafiles.storage.dir=/var/lib/roller/mediafiles
search.index.dir=/var/lib/roller/search-index
cache.dir=/var/lib/roller/planet-cache
log4j.appender.roller.File=${catalina.base}/logs/roller.log
```

`installation.type=manual` means the app expects the schema of §1 to be
there already; `auto` instead stops on an installer page that offers to
create the tables. There is no mail server: the app logs
`Failed to setup mail provider, continuing anyways` at start and runs
without sending mail.

## 4. Run

The WAR's name is the context path:

```bash
rm -rf "$CATALINA_HOME/webapps/roller"*
cp app/target/roller.war "$CATALINA_HOME/webapps/"
"$CATALINA_HOME/bin/catalina.sh" run
```

The app answers on <http://localhost:8080/roller/> ("Welcome to Roller!").
The authoring UI is under <http://localhost:8080/roller/roller-ui/>
(`login.rol`, `register.rol`, `menu.rol`). Tomcat's log is on stdout and
in `$CATALINA_HOME/logs/`; Roller's own log is
`$CATALINA_HOME/logs/roller.log`.
